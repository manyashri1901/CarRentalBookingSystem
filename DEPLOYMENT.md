# Deploying ECar-Ride

Three free services: **MongoDB Atlas** (database), **Render** (API), **Vercel** (frontend).
Do them in that order, because each one needs a value from the step before.

Written for someone deploying this for the first time. Every value you need to type is given,
and anything you must invent yourself is called out.

**Before you start:** merge the code to `main` (see "Merging to main" at the end), because Render and
Vercel deploy from a branch.

---

## Rule 1: secrets never go in the repo

Real passwords and keys are typed into the Render and Vercel dashboards only. The repo contains
`server/.env.example` and `client/.env.example`, which are templates with blank or placeholder values.
Your real `server/.env` is git-ignored and stays on your computer.

## 1. MongoDB Atlas (database)

### 1.1 Create the cluster
1. Go to <https://www.mongodb.com/atlas> and sign up or sign in.
2. **Create a cluster** → choose the **M0 Free** tier.
3. Pick the provider and region closest to you (for India, AWS `ap-south-1` Mumbai).
4. Name the cluster anything, e.g. `ecar-ride`. Click **Create Deployment**. It takes 1-3 minutes.

### 1.2 Create a database user with a NEW password
Atlas may offer to create a user straight away; otherwise go to **Database Access** → **Add New Database User**.

- **Authentication method:** Password
- **Username:** `ecar_app` (anything, but avoid your personal account name)
- **Password:** click **Autogenerate Secure Password** and **copy it now** — Atlas will not show it again.
- **Database User Privileges:** *Read and write to any database*
- Click **Add User**.

> Use a password with no `@ : / ? # [ ] %` characters, or you must URL-encode them in the connection
> string. The autogenerated one is safe.

### 1.3 Allow network access
**Network Access** → **Add IP Address**.

- Render's free tier does not give you a fixed outbound IP, so choose **Allow Access from Anywhere**
  (`0.0.0.0/0`) and click **Confirm**.
- This is normal for free hosting, and the database is still protected by the username and password.
  If you later move to a paid Render plan with a static IP, replace this with that single IP.

### 1.4 Get the connection string
**Database** → **Connect** → **Drivers** → Node.js. You will see something like:

```
mongodb+srv://ecar_app:<db_password>@ecar-ride.ab1cd.mongodb.net/?retryWrites=true&w=majority&appName=ecar-ride
```

Edit it into the form this app expects:

1. Replace `<db_password>` with the password from step 1.2 (remove the angle brackets).
2. Insert the database name `carrental` **between the `/` and the `?`**.

Final shape — keep this somewhere safe, you need it twice:

```
mongodb+srv://ecar_app:YOUR_REAL_PASSWORD@ecar-ride.ab1cd.mongodb.net/carrental?retryWrites=true&w=majority
```

### 1.5 Seed the fleet and create your admin, from your computer
These two commands write to Atlas, so run them locally before deploying.

```bash
cd server
cp .env.example .env          # only if you do not already have server/.env
```

Open `server/.env` and set:

```
MONGO_URI=mongodb+srv://ecar_app:YOUR_REAL_PASSWORD@ecar-ride.ab1cd.mongodb.net/carrental?retryWrites=true&w=majority
```

Then:

```bash
npm install
npm run seed          # loads 14 EVs and 15 charging stations (safe to re-run)
npm run create-admin  # prompts for your admin email and password
```

`npm run seed` prints `Seeded 14 cars and 15 stations.`
`npm run create-admin` prompts for an email and a password of at least 8 characters, and prints
`Created admin account for <you>`. **Write those down — they are the only admin credentials and nothing
in the code knows them.**

**Safety notes**
- `server/.env` is git-ignored. Check with `git status` — it must not appear.
- Your own IP needs to be allowed in Atlas for these commands to work. "Allow Access from Anywhere"
  from step 1.3 covers it.
- If `npm run seed` hangs then fails, the cause is almost always Network Access or a wrong password.

## 2. Render (the API)

### 2.1 Create the service
1. Go to <https://render.com> and sign in with GitHub.
2. **New +** → **Web Service** → **Build and deploy from a Git repository** → **Connect** your
   `CarRentalBookingSystem` repo. Authorise Render to read it if asked.
3. Fill in:

| Field | Value |
|---|---|
| Name | `ecar-ride-api` (becomes your URL) |
| Region | closest to you, e.g. Singapore |
| Branch | `main` |
| **Root Directory** | `server` |
| Runtime | Node |
| **Build Command** | `npm install` |
| **Start Command** | `npm start` |
| Instance Type | **Free** |

Do **not** click Create yet — add the environment variables first.

### 2.2 Environment variables
Scroll to **Environment Variables** → **Add Environment Variable** for each row.

| Key | Value | Where it comes from |
|---|---|---|
| `NODE_ENV` | `production` | type it exactly; it switches on the strict `JWT_SECRET` check |
| `MONGO_URI` | your full Atlas string | step 1.4 |
| `JWT_SECRET` | a long random string | **generate a new one**, see below |
| `CLIENT_ORIGIN` | `http://localhost:5173` for now | you will change this in step 4 |
| `RAZORPAY_KEY_ID` | your test key id | step 5 — or leave both out for demo payments |
| `RAZORPAY_KEY_SECRET` | your test key secret | step 5 |

Generate the JWT secret on your own machine and paste the output:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

It must be at least 32 characters and must not look like a placeholder. **The server refuses to start
in production without a good one** — that is deliberate. Changing it later signs everyone out.

> You do not have to set `PORT`. Render sets it, and the app reads it.

### 2.3 Deploy and check
Click **Create Web Service** and watch the log. You want:

```
MongoDB connected
Server running on port 10000
```

Then open `https://your-service.onrender.com/health` in a browser. A healthy deploy looks like:

```json
{
  "status": "ok",
  "database": "connected",
  "payments": "demo",
  "authSecret": "configured",
  "degraded": false
}
```

**Read that page when something is wrong — it tells you which piece is misconfigured without revealing
any secret.**

| What you see | What it means |
|---|---|
| `"database": "disconnected"` | wrong `MONGO_URI`, wrong password, or Atlas Network Access not open |
| `"authSecret": "weak or missing"` | fix `JWT_SECRET` (in production the service will not start at all) |
| `"payments": "demo"` | no Razorpay keys set; the site shows a labelled Demo payment button |
| service never starts | open the Render log; a `FATAL: JWT_SECRET ...` line is the usual cause |

**Free-tier cold start:** Render spins the service down after about 15 minutes idle. The next request
wakes it and takes **30-60 seconds**. The first page load of the day will feel broken but is not. If you
are demonstrating this live, open the API URL a minute beforehand to wake it.

**Copy your Render URL** (e.g. `https://ecar-ride-api.onrender.com`). You need it next.

## 3. Vercel (the frontend)

1. Go to <https://vercel.com> and sign in with GitHub.
2. **Add New...** → **Project** → **Import** your `CarRentalBookingSystem` repo.
3. Configure:

| Field | Value |
|---|---|
| Framework Preset | **Vite** |
| **Root Directory** | `client` — click **Edit** and pick the `client` folder |
| Build Command | `npm run build` (the default) |
| Output Directory | `dist` (the default) |

4. Expand **Environment Variables** and add one:

| Key | Value |
|---|---|
| `VITE_API_URL` | your Render URL, e.g. `https://ecar-ride-api.onrender.com` — **no trailing slash** |

5. Click **Deploy**, then copy your Vercel URL (e.g. `https://ecar-ride.vercel.app`).

**Refreshing `/cars/tata-nexon-ev` already works:** `client/vercel.json` rewrites every path to
`index.html` so the React router can handle it. (`client/public/_redirects` does the same if you use
Netlify instead.) Test it by opening a car page and pressing refresh — you should see the car, not a 404.

`VITE_API_URL` is baked in at build time, so **changing it needs a redeploy**, not just a save.

---

## 4. Wire them together (CORS)

The API only accepts browser requests from origins you list, so it must now be told about Vercel.

1. Render → your service → **Environment** → edit `CLIENT_ORIGIN`.
2. Set it to your Vercel URL with **no trailing slash**:
   ```
   https://ecar-ride.vercel.app
   ```
   To keep local development working too, use a comma-separated list:
   ```
   https://ecar-ride.vercel.app,http://localhost:5173
   ```
3. **Save Changes.** Render redeploys automatically.

**Check it worked:** open your Vercel site, go to **Cars**, and the 14 EVs should appear. If the page
shows "Cannot reach the server", open the browser console (F12). A message mentioning **CORS** or
`Access-Control-Allow-Origin` means `CLIENT_ORIGIN` does not match your Vercel URL exactly — check for a
trailing slash, `http` vs `https`, or a typo.

> Vercel also gives each deployment a unique preview URL. Those are *not* in `CLIENT_ORIGIN`, so API calls
> from a preview deployment will be blocked. Test on your main `.vercel.app` URL.

## 5. Razorpay (test mode)

Skip this if you are happy with the labelled demo payment button.

1. Sign in at <https://dashboard.razorpay.com>.
2. Switch the toggle to **Test Mode** (top of the dashboard). Make sure it says Test, not Live.
3. **Account & Settings** → **API Keys** → **Generate Test Key**.
4. Copy the **Key Id** (starts `rzp_test_`) and the **Key Secret** (shown once).
5. Render → **Environment** → add:
   - `RAZORPAY_KEY_ID` = the key id
   - `RAZORPAY_KEY_SECRET` = the key secret
6. **Save Changes** and wait for the redeploy. `/health` should now show `"payments": "razorpay"`.

**The key secret goes in Render only.** It never goes in the repo, in Vercel, or in any file you commit.
The browser only ever receives the key id.

**Test card** (Razorpay test mode, no real money):

| Field | Value |
|---|---|
| Card number | `4111 1111 1111 1111` |
| Expiry | any future date, e.g. `12/30` |
| CVV | any 3 digits, e.g. `123` |
| Name | anything |
| OTP, if asked | Razorpay's test page shows a **Success** button to click |

To test a *failed* payment, Razorpay's checkout has a "Force failure" option in test mode, or use their
documented failure card. The site should say the payment failed, leave the booking unpaid, and offer to
try again.

## 6. Final checklist on the live site

Open your Vercel URL and work through this. Expected result in brackets.

**Browsing**
- [ ] Home page loads, the CO2 counter animates *(first load may take 30-60s while Render wakes)*
- [ ] **Cars** shows 14 EVs with photos *(if photos are missing, see "Production differences" below)*
- [ ] Filter by range or brand — the URL changes, and pasting that URL in a new tab keeps the filters
- [ ] Open a car → specs, range gauge and price are shown
- [ ] **Refresh that car page** — it still works (SPA rewrite)
- [ ] **Charging map** shows the map tiles and the station pins; "Use my location" asks permission
- [ ] **Calculator** updates as you change the distance

**Account**
- [ ] **Sign up** with a new email → you are signed in and the navbar shows your name
- [ ] Sign out, then **sign in** again with the same details
- [ ] Wrong password gives "Invalid email or password"

**Booking and payment**
- [ ] Open a car, fill the form, tick **Insurance**, watch the total change
- [ ] **Book now** → the payment page shows the correct total
- [ ] Pay with the Razorpay test card *(or the Demo payment button)*
- [ ] You land on the confirmation page showing **Paid** and a payment id
- [ ] **My bookings** lists it
- [ ] Make a second booking, do not pay, and **cancel** it from My bookings

**Admin**
- [ ] Sign in with the admin account from step 1.5
- [ ] The account menu now shows **Admin**
- [ ] Dashboard shows counts; real revenue and demo payments are listed separately
- [ ] **Cars** tab → **Edit** a car, change the price, save, then check it on the public car page
- [ ] **Add car** with a blank form → it refuses and shows which fields are wrong
- [ ] **Bookings** tab lists bookings from all users
- [ ] Sign out, visit `/admin` directly → you are sent to the login page

**Phone**
- [ ] Open the site on your phone
- [ ] The navbar is a hamburger menu that opens and closes
- [ ] Cars are one per row; the **Filters** button opens a bottom sheet
- [ ] A booking form is usable: fields are big enough and typing does not zoom the page
- [ ] The dark/light toggle works

## What behaves differently in production

| | Local | Production |
|---|---|---|
| **First request** | instant | 30-60s cold start on Render's free tier after ~15 min idle |
| **Database** | optional; without `MONGO_URI` it serves seed JSON and keeps bookings in memory | required; data persists in Atlas |
| **Accounts** | without a database, accounts vanish on restart | stored in Atlas |
| **`JWT_SECRET`** | optional; a random one is generated per restart, so logins drop on restart | **required**; the server refuses to start without a strong one |
| **CORS** | defaults to `http://localhost:5173` | must list your exact Vercel URL |
| **Sign-ins after a redeploy** | n/a | stay valid, because `JWT_SECRET` is fixed. Changing the secret signs everyone out |
| **Rate limiting** | per local IP | per client IP via Render's proxy (`trust proxy` is set to 1) |
| **Payments** | demo button unless you set keys locally | Razorpay test mode once keys are set |
| **`VITE_API_URL`** | read from `client/.env` at dev time | **baked into the build**; changing it needs a Vercel redeploy |
| **Map tiles and car photos** | loaded from the public OpenStreetMap servers / local files | same, but subject to the browser blocking mixed content if anything is `http` |
| **Error detail** | full errors in your terminal | errors are logged on Render; users get a short message |

## Still placeholder data — do not present it as real

| Thing | Status |
|---|---|
| **EV specifications** | Approximate, written from memory. Every car carries `specsApproximate: true` and a note saying what to verify. Check battery, range, charge times and top speed against the manufacturer's official page before showing anyone. |
| **Rental prices** (₹/hour, ₹/day) | Invented. Not market rates. |
| **Insurance ₹299/day, charger ₹499** | Invented. |
| **Charging stations** | 15 illustrative entries with approximate coordinates. **Not live data** and not a real operator list. |
| **Calculator defaults** | Rules of thumb, not citations: 75% real-world range, 10% charging loss, ₹15/kWh, 15 km/L, ₹100/L, 2.31 kg CO2/L, **0.75 kg CO2/kWh grid** — verify this one against the latest CEA CO2 Baseline Database. |
| **Home page CO2 counter** | An illustrative calculation for a 1,000 km example, labelled as such on the page. **Not a real platform total** — no customer has saved this. |
| **Deals** | Three hard-coded offers. |
| **Car photos** | Real cars from Wikimedia Commons under CC licences, credited on each car page. The MG Comet and MG Windsor photos show the Wuling Air EV and Baojun Yunduo, the same cars under different badges, noted on their pages. |
| **Ratings** | Invented numbers, not customer reviews. |
| **Contact details** | Placeholder address, phone and email. |
| **Demo payments** | When Razorpay keys are not set, bookings can be marked "paid (demo)". No money moves and the UI says so. |

## Merging to main

Nothing is pushed yet. When you are ready:

```bash
# 1. push the branches
git push -u origin responsive-ui
git push -u origin ecar-ride-ev

# 2. open a pull request from ecar-ride-ev into main
gh pr create --base main --head ecar-ride-ev \
  --title "ECar-Ride: EV rental platform" \
  --body-file .github/PR_BODY.md
```

No `gh` CLI? After pushing, GitHub shows a **Compare & pull request** button on the repo page, or go to
`https://github.com/manyashri1901/CarRentalBookingSystem/compare/main...ecar-ride-ev` and press
**Create pull request**. Paste the text from `.github/PR_BODY.md` as the description.

`ecar-ride-ev` already contains every commit from `responsive-ui`, so the one pull request covers all the
work. Pushing `responsive-ui` as well just makes the history easier to read.

**Merge** the pull request on GitHub when you are happy with it. Render and Vercel then deploy from `main`.
